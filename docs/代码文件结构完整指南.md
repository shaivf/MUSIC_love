错误机制的整体架构设计：

```   
1️⃣ 错误处理是“链式传播”，不是“并行检测”
      错误发生
         ↓
      逐层向上冒泡
         ↓
      谁先拦住，谁先处理

2️⃣ 各层优先级（从近到远）
      1️⃣ useAsyncError（业务逻辑层）
      2️⃣ onErrorCaptured（组件层）
      3️⃣ app.config.errorHandler（Vue层）
      4️⃣ window.error / unhandledrejection（浏览器层）

3️⃣ 是否继续传播，取决于：
      return false（Vue）
      是否 catch
      是否 Promise.reject

完整的错误架构
      useAsyncError（异步入口）
         ↓
      onErrorCaptured（组件边界）
         ↓
      app.config.errorHandler（Vue 全局）
         ↓
      window.error / unhandledrejection（浏览器兜底）
         ↓
      errorBoundary.js（统一状态）
         ↓
      GlobalErrorBoundary.vue（UI 展示）

### 🔐 第二阶段：用户认证系统

**从登录/注册开始，理解认证流程**

#### 前端认证
```
⭐ frontend/src/pages/Login.vue
   ├─ 登录表单 UI
   ├─ 使用 useAsyncError 管理 loading 和错误

⭐ frontend/src/pages/Register.vue
   ├─ 注册表单 UI
   ├─ 使用 useAsyncError 管理 loading 和错误
   └─ 调用 userStore.register()

📄 frontend/src/api/index.js (统一的 API 层)
   ├─ userApi.login(data)          → POST /auth/login
   ├─ userApi.register(data)       → POST /auth/register
   ├─ userApi.logout()             → POST /auth/logout
   ├─ userApi.getProfile()         → GET /user/profile
   ├─ userApi.updateProfile(data)  → PUT /user/profile
   ├─ userApi.getMySongs()         → GET /user/songs
   ├─ userApi.getPlayHistory()     → GET /user/history
   └─ userApi.recordPlayHistory()  → POST /user/history

📄 frontend/src/stores/user.js (状态管理和业务逻辑)
   ├─ state: token, user, isAuthenticated

   ├─ login() - 调用 userApi.login()，保存 token 和 user，存储到 localStorage
   ├─ logout() - 清除 state 和 localStorage
   ├─ getProfile() - 获取个人信息
   └─ updateProfile() - 更新个人信息

📄 frontend/src/utils/useAsyncError.js (错误处理组合函数)
   ├─ loading - 响应式加载状态
   ├─ execute(asyncFn, errorMsg) - 统一执行异步操作并处理错误
   └─ withLoading(asyncFn) - 仅管理加载状态

📄 frontend/src/utils/auth.js（已移除）
   └─ 相关能力已并入 `stores/user.js`（Token 管理）与表单页面本地校验逻辑

📄 frontend/src/utils/http.js
   ├─ 创建 Axios 实例
   ├─ 请求拦截器：自动附加 Authorization header
   └─ 响应拦截器：统一处理错误
```

**🔑 关键改进（2026-04-22）**：
- ✅ **统一 API 层**：将所有认证 API 整合到 `userApi` 中（从单独的 `auth.js` 整合）
- ✅ **一致的错误处理**：所有页面使用 `useAsyncError` 替代手动 `try/catch`
- ✅ **清晰的职责分工**：
  - API 层（`index.js`）：纯 HTTP 请求包装
  - Store 层（`user.js`）：业务逻辑和状态管理
  - 页面层：UI 和交互

#### 后端认证
```
📄 backend/src/routes/auth.js
   ├─ POST /register
   ├─ POST /login
   └─ 调用 authController

⭐ backend/src/controllers/authController.js
   ├─ register(req, res)
   │  ├─ 验证邮箱格式
   │  ├─ 检查邮箱是否已注册

   │  ├─ 保存到 users 表
   │  └─ 返回新用户信息
   │
   └─ login(req, res)
      ├─ 查询 users 表找邮箱对应用户
      ├─ 验证密码
      ├─ 生成 JWT token
      └─ 返回 token + user

📄 backend/src/config/jwt.js
   ├─ JWT_SECRET 常量
   ├─ generateToken(userId) - 生成 JWT
   ├─ verifyToken(token) - 验证 JWT
   └─ authMiddleware - 中间件，验证请求的 token

📄 backend/src/utils/helpers.js
   ├─ isValidEmail(email)
   ├─ isValidPassword(password)
   └─ isValidPhoneNumber(phone)

📄 backend/src/utils/response.js
   ├─ sendSuccess(res, data, message)
   └─ sendError(res, code, message)
```

## 📊 完整交互流程

### 🔐 用户认证流程

```
┌─────────────────────────────────────────────────────────────┐
│                     用户认证完整流程                          │
└─────────────────────────────────────────────────────────────┘

1. 前端：用户在 Login.vue 输入邮箱和密码
   ↓
2. 前端：点击登录按钮 → 调用 userStore.login()
   ↓
3. 前端 (Pinia): userStore 调用 auth.js 的 login() 函数
   ↓
4. 前端 (API): auth.js 通过 http.js 发送 POST /api/auth/login 请求
   ↓
5. 前端 (HTTP): http.js 请求拦截器添加 headers（首次登录无 token）
   ↓
6. 后端 (路由): routes/auth.js 处理 POST /auth/login 路由
   ↓
7. 后端 (控制器): authController.js 的 login() 函数
   ├─ 查询数据库：从 users 表找邮箱对应用户
   ├─ 密码验证：bcryptjs 比对密码
   ├─ 生成 Token：调用 jwt.js 的 generateToken() 生成 JWT
   └─ 返回响应：{ success: true, token, user }
   ↓
8. 前端 (HTTP): http.js 响应拦截器收到响应
   ├─ 检查 success 字段
   └─ 返回数据或抛出错误
   ↓
9. 前端 (Pinia): userStore 接收响应
   ├─ 保存 token 到 state
   ├─ 保存 user 信息到 state
   └─ 保存到 localStorage
   ↓
10. 前端 (路由): 成功则导航到 /user（用户中心）
   ↓
11. 后续请求: 所有请求都会自动附加 token：Authorization: Bearer <token>
```

### 🎵 歌曲上传流程

```
┌─────────────────────────────────────────────────────────────┐
│                     歌曲上传完整流程                          │
└─────────────────────────────────────────────────────────────┘

1. 前端：用户在 UserCenter.vue 选择音频和封面文件
   ↓
2. 前端：创建 FormData 对象
   ├─ audio: File (mp3/wav)
   ├─ cover: File (jpg/png)
   ├─ title: String
   ├─ artist: String
   └─ album: String
   ↓
3. 前端：调用 songs.js 的 uploadSong(formData, onUploadProgress)
   ↓
4. 前端 (HTTP): http.js 发送 POST /api/songs
   ├─ Content-Type: multipart/form-data
   ├─ Authorization: Bearer <token> (自动附加)
   └─ 上传进度回调 onUploadProgress
   ↓
5. 前端 (UI): 显示进度条，实时反馈上传进度百分比
   ↓
6. 后端 (中间件): middleware/upload.js (Multer)
   ├─ 拦截 multipart/form-data
   ├─ 验证文件类型和大小
   ├─ 保存音频到 src/uploads/songs/
   ├─ 保存封面到 src/uploads/covers/
   └─ 将文件信息放入 req.files
   ↓
7. 后端 (路由): routes/song.js 第一个路由 (POST /)
   ├─ 执行 authMiddleware （验证 token）
   ├─ 执行 upload.fields() （处理文件）
   ├─ 调用 songController.upload()
   ↓
8. 后端 (控制器): songController.upload()
   ├─ 提取文件路径：/uploads/songs/xxx.mp3
   ├─ 提取歌曲元数据：title, artist, album, duration
   ├─ 构建数据对象：{ title, artist, album, audio_url, cover, uploader_id: req.user.id }
   ├─ INSERT INTO songs 表
   └─ 返回新建歌曲记录
   ↓
9. 前端：接收成功响应
   ├─ 显示成功提示
   └─ 刷新用户的歌曲列表
```

## 🎯 后端架构设计（MVC 规范）

### 架构演进

**重构前 (不规范)**:
- ❌ `routes/user.js` 混合了路由、业务逻辑、辅助函数 (1200+ 行)
- ❌ 辅助函数重复定义在 songController.js 和 user.js
- ❌ 响应格式不统一

**重构后 (规范 MVC)**:
- ✅ `routes/user.js` - 仅路由定义 (30 行)
- ✅ `controllers/userController.js` - 所有业务逻辑 (400+行)
- ✅ `utils/helpers.js` - 统一的辅助函数库
- ✅ 所有 controller 统一使用 `sendSuccess/sendError`

### 三层架构说明

```
请求到达
    ↓
1️⃣ 路由层 (routes/*.js)
   • 定义 API 端点和 HTTP 方法
   • 组织中间件和请求处理
   • 示例：router.get('/profile', authMiddleware, userController.getProfile)
    ↓
2️⃣ 业务逻辑层 (controllers/*.js)
   • 处理核心业务逻辑
   • 与数据库交互
   • 数据验证和转换
   • 示例：export async function getProfile(req, res, next) { ... }
    ↓
3️⃣ 工具层 (utils/)
   • helpers.js - 数据验证、格式化、分页
   • response.js - 统一的响应格式
   • 示例：parsePositiveInt(), sendSuccess()
    ↓
💾 数据库 (config/database.js)
   • 连接池管理
   • SQL 执行
```

## 🔧 常见问题和解决方案

### 问题 1: 前端页面空白，控制台错误 "doesn't provide an export named 'XXX'"

**症状**:
```
Uncaught SyntaxError: The requested module '/node_modules/.vite/deps/@element-plus_icons-vue.js' 
does not provide an export named 'Music' (at MusicBar.vue:59:23)
```

**原因**:
- Element Plus Icons 库的导出名称与预期不符
- 某些版本的库可能不包含特定的图标

**解决方案**:
1. 查看 `frontend/src/components/` 和 `frontend/src/pages/` 中是否有导入不存在的图标
2. 选择解决方案之一：
   - **方案 A (推荐)**: 改用 emoji 或 Unicode 字符
     ```vue
     <!-- 旧方式（失败） -->
     <el-icon><Music /></el-icon>
     
     <!-- 新方式（成功） -->
     🎵
     ```
   - **方案 B**: 使用其他图标库（Font Awesome, Heroicons）
   - **方案 C**: 使用 SVG 直接导入

**已修复的文件**:
- ✅ `MusicBar.vue` - 使用 emoji (▶️ ⏸ 🎵 ⛶ 📋)
- ✅ `Home.vue` - 使用 emoji (🎵 👤 ▶️)
- ✅ `Login.vue` - 使用 emoji (📧 🔒)
- ✅ `Register.vue` - 使用 emoji (📧 🔒)
- ✅ `Songs.vue` - 使用文本 "⏳"
- ✅ `Player.vue` - 转换为文本按钮 "← 返回"
- ✅ `UserCenter.vue` - 使用文本 "⏳"

### 问题 2: HTML 元素挂载失败

**症状**:
```
Vue 应用无法挂载到 #app，页面完全空白
```

**原因**:
- `App.vue` 中的元素 ID 与 `index.html` 中的挂载点冲突
- 例如：同时有 `<div id="app" class="app">` 和 `<div id="app"></div>`

**解决方案**:
```vue
<!-- 错误 -->
<div id="app" class="app"><!-- 会与 index.html 的 <div id="app"></div> 冲突 --></div>

<!-- 正确 -->
<div class="app-container"><!-- 使用不同的 class，不重复 id --></div>
```

**已修复**:
- ✅ `App.vue` - 改为 `<div class="app-container">`

## 🎯 总结

本项目是一个**完整的前后端分离架构**：

- **后端**: Node.js + Express + MySQL + JWT + Multer
  - 15 个文件，职责分明（路由 → 控制器 → 业务逻辑 → 数据库）

  - 18 个文件，模块化设计（API 层 → 状态管理 → 组件 → 页面）
  - 6 个主页面，完整的用户交互流程
  - 路由守卫、权限控制、错误处理

- **部署**: Docker Compose + Nginx
  - 一键启动三个服务（MySQL、Backend、Frontend）
  - 生产级别配置和监控
